# USD — подключение обычной Яндекс Почты

Согласованный отправитель: **usd-russia@yandex.ru** (личный бесплатный ящик, не Яндекс 360 для бизнеса).

Статус: код и пример переменных подготовлены. **Доставка писем не считается
настроенной**, пока в защищённом окружении Ubuntu не введён пароль приложения,
не проверена доступность SMTP и не получено реальное письмо.

## 1. Подготовить аккаунт Яндекса

1. Открыть один раз [Яндекс Почту](https://mail.yandex.ru/) и принять условия сервиса.
2. В настройках Почты → «Почтовые программы» разрешить доступ через почтовые клиенты
   и «Пароли приложений и OAuth-токены» (если это требуется аккаунтом).
3. В [Яндекс ID → Пароли приложений](https://id.yandex.ru/security/app-passwords)
   создать отдельный пароль для **Почты**, например «USD Ubuntu API».
   Этот пароль показывается только один раз. **Не пересылать его в чат, GitHub
   или журнал GitHub Actions.** Основной пароль Яндекс ID использовать нельзя.

Официальные параметры SMTP: `smtp.yandex.ru`, SSL/TLS, порт `465`.
Для личного ящика Яндекс указывает логин до символа `@`: `usd-russia`.
Смотрите [инструкцию Яндекса](https://www.yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

## 2. Проверить соединение с Ubuntu

Выполнять в Ubuntu VM, а не на основном Windows-хосте:

```bash
python3 - <<'PY'
import socket
try:
    with socket.create_connection(("smtp.yandex.ru", 465), timeout=8):
        print("TCP 465: доступен")
except OSError as exc:
    print("TCP 465: недоступен; не включайте SMTP_EGRESS_ALLOWED:", type(exc).__name__)
PY
```

Это проверяет только сетевой доступ, не пароль и не доставку. Если выходной порт
заблокирован домашним провайдером/виртуальной сетью, **не пытайтесь слепо
перезапускать сервис**. В таком случае нужен разрешённый канал отправки
(например, HTTPS-провайдер), а не многократные SMTP-повторы.

## 3. Ввести секрет только на Ubuntu

После подтверждения доступа к `smtp.yandex.ru:465` открыть существующий файл
`/home/usd/usd-deploy/deploy/home-pc/.env`:

```bash
sudoedit /home/usd/usd-deploy/deploy/home-pc/.env
```

Добавить/обновить **ровно по одному** экземпляру каждого ключа:

```dotenv
MAIL_PROVIDER=smtp
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=usd-russia
SMTP_FROM="USD <usd-russia@yandex.ru>"
SMTP_PASSWORD=ПАРОЛЬ_ПРИЛОЖЕНИЯ_ИЗ_ЯНДЕКС_ID
SMTP_EGRESS_ALLOWED=true
```

`SMTP_PASSWORD` заменить на секрет из Яндекса в редакторе. Не вставлять его
в команды `echo`, сообщение, скрипт или репозиторий. При особых символах
проверить корректность quoting через `docker compose config`, **не печатая**
полный конфиг в терминал или логи. Ограничить доступ к файлу:

```bash
sudo chmod 600 /home/usd/usd-deploy/deploy/home-pc/.env
```

`MAIL_PROVIDER=smtp` выбран специально: старые переменные `GMAIL_*` и
`RESEND_*` не смогут перехватить новые обязательные письма. Настройки
Google OAuth для входа на сайт менять не нужно.

**Важно:** секрет остаётся только в локальном файле окружения. Не добавляйте
`.env` в git и не присылайте результаты команды, раскрывающей значения
переменных.

## 4. Применить и протестировать

1. Убедиться, что на сервере развернут API из `main` с поддержкой
   `MAIL_PROVIDER=smtp`. Не менять рабочий образ и не обходить штатные
   проверки релиза ради настройки почты.
2. Применить новое окружение, **пересоздав только API** с тем же набором
   Compose-файлов, с которым он уже работает. Не перезапускать БД, S3
   или Caddy. Если настройки ещё не готовы, оставить работающий API без изменений.
3. Войти под ADMIN: **Админка → Тестирование писем → Проверить настройки**.
   Должно появиться «Яндекс Почта (SMTP)», статус готовности и пустой
   список отсутствующих параметров.
4. Отправить тестовые **«Подтверждение email аккаунта»**, **«Восстановление
   пароля»**, **«Подтверждение нового email»** на собственный ящик.
   Проверить входящие и спам. Ответ «провайдер принял» **не является доказательством
   доставки**, поэтому нужны реально полученные письма.
5. Отдельно проверить реальную регистрацию нового тестового аккаунта и
   восстановление пароля: URL должен указывать на
   `https://app.usd-russia.ru`, а одноразовые токены — работать.

Личный ящик не следует использовать для массовых анонсов и частых
автоматических рассылок. По плану USD новости и напоминания об этапах
передаются через PUSH. Не включать массовую почтовую рассылку до отдельной
проверки политики Яндекса, согласий и лимитов.

Ни один из этих шагов не меняет основной `usd-russia.ru`.
