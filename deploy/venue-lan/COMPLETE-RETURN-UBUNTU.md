# USD — возврат настоящего этапа с ноутбука на Ubuntu

**Для ответственного администратора сервера, не для судьи.** Нельзя выполнять на боевой базе до резервного копирования, dry-run и сверки результатов. Основной домен и публичные соревнования не изменяются кнопкой на ноутбуке. Не передавайте закрытый ключ ноутбука или серверные пароли.

## На площадке

1. Судьи заканчивают изменения. Администратор нажимает **«USD — Онлайн»**. Для НАСТОЯЩЕГО этапа эта кнопка **сначала** создаёт подписанный AES-256-GCM файл, и только после успешного сохранения останавливает локальный сервер. Если передача прервётся — данные остаются на ноутбуке и соревнования можно снова открыть кнопкой **«USD — Офлайн»**.
2. В папке `local-private/return-output` находятся `usd-venue-return-<этап>-<время>.json`, `USD-Venue-Return-Public.pem`, `USD-Venue-Return-Fingerprint.txt`.
3. Передайте файл и публичный ключ ответственному за Ubuntu по защищённому каналу. Пароль шифрования передайте **отдельно**; отпечаток ключа сверьте по независимому каналу. Никогда не отправляйте `.env`, базу локальных аккаунтов или закрытый ключ.
4. Ничего не удаляйте, не переустанавливайте ноутбук и не выполняйте Docker `down -v` до официальной сверки и резервной копии.

## На центральной Ubuntu

**Предварительные условия:** исходный stage UUID, SHA256 исходного подписанного этапа (baseline), отпечаток публичного ключа площадки подтверждены независимо, контейнеры и схема PostgreSQL 18 актуальны, центральная база сохранена на второй диск и резервная копия проверена в изолированном восстановлении. Заблокируйте новые центральные записи этого этапа на время импорта; серверное приложение не должно параллельно публиковать результаты. Изменения в общих данных должны быть проверены отдельно.

Команда доступна как **строго операторский** CLI, а не публичный HTTP API, и не требует доступа к личным учётным данным судей:

```bash
cd /opt/usd-release-source/backend
# Node.js и npm ci для этой версии backend должны быть доступны в защищённой maintenance-среде
export DATABASE_URL='<проверенный_URL_центральной_БД>'
export VENUE_RETURN_STAGE_ID='<UUID_этапа>'
export VENUE_RETURN_BASELINE_SHA256='<64_hex_SHA_исходного_этапа>'
export VENUE_RETURN_TRUSTED_FINGERPRINT='<64_hex_SHA_публичного_Ed25519_ключа>'
export VENUE_RETURN_OPERATOR='<идентификатор_администратора>'
read -r -s -p 'Пароль USB-пакета: ' USD_TRANSFER_PASSWORD; echo
printf '%s' "$USD_TRANSFER_PASSWORD" | node scripts/apply-complete-venue-return.mjs \
  /secure/venue-return.json /secure/USD-Venue-Return-Public.pem --dry-run
```

Убедитесь, что dry-run сообщает `readyEvents` для **всего** журнала и не создаёт ни одной сохраняемой записи. Сравните количество регистраций, номеров, классов, инспекций и результатов с ноутбуком, проверьте фотографии и активные дисквалификации. Любой `CONFLICT` означает **СТОП**, возврат к локальным данным и ручное расследование. Не изменяйте checksum или историю миграций ради обхода.

Только после отдельной проверки резервной копии:

```bash
export VENUE_RETURN_BACKUP_VERIFIED="$VENUE_RETURN_STAGE_ID"
export VENUE_RETURN_APPLY_CONFIRM="$VENUE_RETURN_STAGE_ID"
printf '%s' "$USD_TRANSFER_PASSWORD" | node scripts/apply-complete-venue-return.mjs \
  /secure/venue-return.json /secure/USD-Venue-Return-Public.pem --apply
unset USD_TRANSFER_PASSWORD
```

Импорт выполняется одной SERIALIZABLE-транзакцией, с текущими центральными проверками допуска, классов и номерных конфликтов, записью audit receipts. Повторная отправка **того же подписанного пакета** безопасна; внешний пересчёт рейтингов/рекордов производится повторно, если предыдущая попытка прервалась. Результаты **не публикуются автоматически**. Система возвращает код **4** даже после успешного DB commit: он означает, что перенос и полевые проверки **НЕ приняты целиком**.

## Важные ограничения

- Подписанный пакет версии **2** должен подтверждать все 19 root-owned триггеров **с самой первой операции**. Старый локальный журнал без усилителя→динамика не имеет права заявить полный перенос; после безопасного обновления требуется ручная сверка старых событий.
- Если на площадке добавлялись или изменялись фотографии, полный импорт **блокируется** до отдельного переноса бинарных изображений из RustFS. Перенаправлять локальные URL на центральные без реальной копии файлов нельзя.
- Изменения опубликованности этапа и дисквалификации требуют отдельного согласования. Импорт не должен автоматически заменять эти решения центрального администратора.
- После успешного DB импорта отдельно проверьте БД, фотографии, отчёты, record/ranking rebuild, LIVE-результаты, опубликованные протоколы. Только администратор после физического теста и приёмки на Ubuntu может объявить этап перенесённым и разрешить очистку локальных данных.
