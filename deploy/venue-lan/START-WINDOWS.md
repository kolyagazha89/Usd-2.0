# USD — установка настоящего офлайн-этапа на Windows

Работайте на ноутбуке Windows 10/11 с Docker Desktop и выделенным Wi-Fi-роутером судей. Основную Ubuntu эти действия не изменяют.

## 1. Скачайте три файла в основной админке

В разделе **Офлайн-сервер → Подготовка файла настоящего этапа** выберите опубликованный этап.
Последовательно нажмите **«Скачать файл этапа»**, **«Скачать ключ судей (.key)»** и
**«Скачать открытый ключ (.pem)»**. Запишите показанный на защищённой странице
отпечаток Ed25519 отдельно от этих файлов. JSON действует 72 часа.
Ключ `.key` нельзя отправлять в чат или хранить в общедоступной папке.

## 2. Получите новую программу

В основной админке нажмите **«Скачать для Windows»** и извлеките ZIP.

**Если на этом ноутбуке уже стоит старая пробная установка:** откройте старую
папку `USD-Offline-Windows` (где есть `.env` и `local-private`).
Скопируйте **содержимое** новой папки поверх старой с заменой файлов программы,
при этом **не удаляйте** `.env` и `local-private`. Не запускайте
новый установщик из второй папки: используйте первоначальную рабочую папку.
Для всех новых настоящих этапов программа использует **тот же Docker-проект и ту же PostgreSQL**. Предыдущие результаты не очищаются.

В новой программе **нет режима ДЕМО**. При запуске из старой папки мастер
проверит, что существующая база действительно является завершённым старым
пробным запуском, затем **отдельно спросит разрешение на безвозвратное удаление**
её Docker-томов. Если видит реальные данные, чужие контейнеры, экспорт или
повреждённые метаданные — удаление блокируется. Основная Ubuntu не затрагивается.

## 3. Установите настоящий этап

1. Подключите ноутбук к судейскому Wi-Fi с частным IP. Сделайте Windows-профиль сети **«Частная»**.
2. Убедитесь, что Docker Desktop запущен в режиме Linux containers / WSL2.
3. Дважды нажмите `USD-Install.cmd` в нужной папке. Если обнаружен старый
   тестовый сервер, проверьте предупреждение и подтвердите замену, если удаление
   данных допустимо.
4. Выберите Wi-Fi-адаптер и подтвердите разрешение брандмауэра Windows (только TCP 443 локальной подсети).
5. Выберите скачанный JSON, открытый ключ `.pem`, введите отпечаток с
   защищённой страницы админки и укажите отдельный файл `.key`.
6. Подтвердите загрузку подписанного этапа. При ошибке не удаляйте Docker-тома:
   снова запустите тот же `USD-Install.cmd`.

Программа проверит SHA образов и подпись пакета, создаст отдельные
PostgreSQL 18 и RustFS, загрузит участников, автомобили, регистрации,
права ADMIN и судей, после чего откроет `https://IP-ноутбука/login`.
Администратор и судьи входят **обычными аккаунтами USD**, без новых паролей.
Табло: `https://IP-ноутбука/venue/live`.

## 4. Настройте телефоны и проверьте площадку

Телефоны и ноутбук должны быть подключены к одному Wi-Fi. Сохранённый
публичный корневой сертификат `local-private/USD-Venue-CA.crt` нужно доверить
на каждом устройстве, предварительно убедившись, что он получен от вашего
ноутбука. Не пересылайте всю папку `local-private`.

На iPhone: «Настройки» → «Профиль загружен» → «Установить», затем
«Основные» → «Об этом устройстве» → «Доверие сертификатам» →
включить доверие к этому локальному CA. На Android: настройки безопасности →
установка пользовательского CA. На Windows: импорт этого CA в
«Доверенные корневые центры сертификации» текущего пользователя.

Проверьте с двух телефонов регистрацию, инспекцию, ввод и LIVE-табло,
отключив WAN/мобильный интернет, затем перезагрузите ноутбук и повторите
проверку данных. Автозапуск выполняется после входа пользователя в Windows.
Без такого испытания не проводите официальный этап.

## 5. Возврат результатов

`USD-Export.cmd` создаёт зашифрованную резервную копию (не означает
синхронизацию). `USD-Online.cmd` останавливает судейский ввод, делает
подписанный возврат, передаёт его на Ubuntu и ждёт подтверждения всех записей
и пересчёта результатов. При ошибке он сохраняет данные и восстанавливает
локальный API. Никогда не выполняйте `docker compose down -v` вручную
для настоящего этапа.

После принятого ACK локальная база и секреты всё равно сохраняются,
пока администратор не подтвердит сверку. Полная физическая приёмка с
Ubuntu обязательна перед соревнованиями.

## 6. Следующий этап — одна PostgreSQL на весь сезон

1. В основной админке USD скачайте свежие `.json`, `.key` и `.pem`
   **нового этапа** и запишите отпечаток подписи.
2. Откройте **`USD-Next-Stage.cmd`** или ярлык **«USD — Следующий этап»**
   в той же папке уже работающего USD. Установщик и Docker заново не создавайте.
3. Программа остановит судейский ввод, проверит точный хеш текущего журнала
   и подтверждение Ubuntu. Если появились изменения — сначала передаст их.
   При отказе или ошибке сети новая регистрация не начнётся.
4. Перед импортом сохранится дамп PostgreSQL в защищённой папке
   `local-private/stage-history/<UUID старого этапа>`. Он содержит личные
   данные: храните ноутбук и копию на защищённом диске.
5. Подписанный новый этап атомарно добавится в **ту же PostgreSQL**.
   Участники, автомобили, исторические регистрации и результаты остаются,
   повторяющиеся центральные идентификаторы не перезаписываются.
6. Список доступных судей обновится по отдельному подписанному `.key`.
   Результаты следующего этапа вводятся в тот же локальный USD. При
   экспорте передаётся **только журнал активного этапа**.
7. Если ноутбук выключится во время перехода, откройте
   `USD-Install.cmd` в **той же папке**: безопасное завершение продолжится.
   Не удаляйте `.env`, `local-private` или Docker-тома вручную.

Локальный HTTPS-сертификат и Wi-Fi остаются прежними: повторно доверять
новый CA на телефонах не нужно. Старые результаты доступны как история
в единой базе. Это **не отдельная аппаратная резервная копия**: для
устойчивости к поломке SSD нужен ещё один зашифрованный бэкап на другом
носителе.
