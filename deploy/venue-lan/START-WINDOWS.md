# USD — установка настоящего офлайн-этапа на Windows

Работайте на ноутбуке Windows 10/11 с Docker Desktop и выделенным Wi-Fi-роутером судей. Основную Ubuntu эти действия не изменяют.

## 1. Подготовьте доступ ADMIN в онлайн-USD

В новом окне `USD-Control.cmd` нажмите **«Войти в USD»**, войдите как ADMIN, выберите опубликованный этап и нажмите **«Загрузить этап»**. Приложение само получит подписанный JSON, открытый PEM и отдельный AES-ключ судей по HTTPS из официального API, сверит отпечаток с ADMIN-only настройкой сервера и положит файлы в папку с ограниченными правами. Данные входа и токен остаются только в памяти на время загрузки, не сохраняются в файл. Пакет действует 72 часа. Если онлайн недоступен, остаётся старый ручной установщик.

**Важно:** кнопка «Обновить участников и автомобили» добавляет только справочник и конфигурации, **не** новые регистрации уже установленного этапа. Для следующего этапа приложение скачает полный новый пакет.

## 2. Получите программу с единым окном управления

В основной админке нажмите **«Скачать для Windows»** и извлеките ZIP. Запустите **`USD-Control.cmd`**: теперь это единое окно оператора. После установки на рабочем столе появится **один** ярлык «USD — Офлайн-сервер» вместо отдельных ярлыков для каждой операции.

**При обновлении:** откройте рабочую папку существующего ярлыка, затем закройте окно управления.
Скопируйте **содержимое** новой папки поверх старой с заменой файлов программы,
при этом **не удаляйте** `.env` и `local-private`. Не запускайте
новый установщик из второй папки: используйте первоначальную рабочую папку.
Следующие этапы добавляются в тот же проект Docker и ту же базу PostgreSQL.

Для обновления компонентов сервера используйте «Установить или обновить сервер»: программа сверит опубликованные версии API и сайта, загрузит новый frontend и перезапустит только frontend и HTTPS-шлюз. Локальные API, база, результаты и сертификат сохраняются. При отсутствии интернета продолжится работа установленной версии; при ошибке включения нового экрана программа вернёт прежний frontend.

При обнаружении старой пробной базы установка остановится. Для сохранения её данных и перехода на рабочую установку обратитесь к администратору USD.

## 3. Установите настоящий этап

1. Подключите ноутбук к судейскому Wi-Fi с частным IP. Сделайте Windows-профиль сети **«Частная»**.
2. Убедитесь, что Docker Desktop запущен в режиме Linux containers / WSL2.
3. В окне USD нажмите «Войти в USD», выберите этап и нажмите «Загрузить этап».
4. Выберите Wi-Fi-адаптер и подтвердите запрос брандмауэра для доступа к портам 80 и 443 из локальной сети.
5. Дождитесь проверки готовности API и HTTPS. Если установка прервётся, нажмите «Продолжить загрузку». В окне ошибки доступны повтор и технические подробности.

При первой установке программа предпочитает текущую опубликованную версию,
даже если в Docker есть старые образы. Она проверяет `api.usd-russia.ru/release`, затем
`app.usd-russia.ru/usd-release.json`. Если оба сервера недоступны, использует
проверенные образы из локального кеша. Если подходящего кеша нет, скачивает
проверенную опубликованную резервную версию USD
напрямую из `ghcr.io` (GitHub Container Registry). Поэтому доступ к сайтам USD
во время установки не обязателен, **но доступ к GHCR или заранее скачанные
подходящие Docker-образы необходимы**. При ошибке проверьте `ghcr.io`, не
удаляйте контейнеры, образы или тома.

Установщик показывает текущий шаг. Если ошибка повторяется, отправьте администратору подробности из окна ошибки или журнала операций. Если консоль уже запущена администратором, отдельное окно UAC для брандмауэра не требуется.

Программа проверит SHA образов и подпись пакета, создаст отдельные
PostgreSQL 18 и RustFS, загрузит участников, автомобили, их существующие конфигурации
со всеми версиями и оборудованием, регистрации, права ADMIN и судей, после чего откроет `https://IP-ноутбука/login`.
Администратор и судьи входят **обычными аккаунтами USD**, без новых паролей.
LIVE на телевизоре без сертификатов: `http://IP-ноутбука/venue/live`. Показывает только реальные результаты текущего этапа. Автосмена классов: 9 секунд; обновление данных: 4 секунды. SPL — отдельный экран, BFSPL + BDW SPL — второй экран.

**Комплектации:** у существующего участника после установки доступны те же
конфигурации, версии и комплектующие, что были в онлайн USD на момент
создания подписанного файла. У нового участника, которого создали на въезде,
при регистрации на месте автоматически создаётся только служебный черновик:
участник заполнит оборудование после этапа. Это не повод задерживать замер.

**Важно для уже проведённых этапов:** обновление программы и скачивание
нового файла не перезаписывают существующие локальные результаты и не превращают
ранее созданные заглушки в настоящие конфигурации. Не переустанавливайте
активный этап и не удаляйте тома Docker ради оборудования. Сохраните экспорт
и дождитесь отдельной проверенной процедуры возврата конфликтующих данных.

## 4. Настройте телефоны и проверьте площадку

Телефоны и ноутбук должны быть подключены к одному Wi-Fi. **Для телевизора сертификат не нужен: используйте HTTP-ссылку LIVE выше.** Только для входа судей по HTTPS сохранённый
публичный корневой сертификат `local-private/USD-Venue-CA.crt` нужно доверить
на каждом устройстве, предварительно убедившись, что он получен от вашего
ноутбука. Не пересылайте всю папку `local-private`.

После первого успешного запуска нажмите **USD-Certificate.cmd** в рабочей
папке (или ярлык **«USD — Сертификат»**). Caddy может ещё выпускать CA: мастер
повторяет получение до 30 секунд, проверяет корневой X.509 и сохраняет **два
одинаковых публичных файла**:
`USD-Offline-Windows/USD-Venue-CA.crt` (рядом с USD-Install.cmd) и
`USD-Offline-Windows/local-private/USD-Venue-CA.crt`. Никакой `root.key` не
скачивается. В консоли будет SHA-256, который нужно сверить при раздаче.

Зайдите в **онлайн-админку USD → Офлайн-сервер → Сертификат HTTPS для телефонов**,
один раз загрузите **только USD-Venue-CA.crt** с ноутбука. Затем на телефоне
прямо из админки или по QR скачайте публичный сертификат: **.cer для iPhone** и
**.crt для Android**. Нажмите «Скопировать ссылку для MAX» и отправьте судьям ссылку на страницу установки, а не сам файл сертификата. На странице доступны .cer/.crt и инструкция; QR открывает ту же страницу. При открытии внутри MAX на iPhone скопируйте адрес в Safari. Ссылки работают и для судей без входа в админку, но
разрешать установку следует только после сверки SHA-256. При смене Caddy CA
повторите выгрузку и замените файл в онлайн-админке.

На iPhone: открыть .cer в Safari → «Профиль загружен» → «Установить», затем
«Основные» → «Об этом устройстве» → «Доверие сертификатам» →
включить доверие к этому локальному CA. На Android: настройки безопасности →
установка CA (название пункта зависит от модели). На Windows: импорт этого
CA в «Доверенные корневые центры сертификации» текущего пользователя.

Проверьте с двух телефонов регистрацию, инспекцию и ввод. Введите один реальный результат и проверьте, что он появился на LIVE-табло,
отключив WAN/мобильный интернет, затем перезагрузите ноутбук и повторите
проверку данных. Автозапуск выполняется после входа пользователя в Windows.
Без такого испытания не проводите официальный этап.

## 5. Возврат результатов

«Сохранить резервную копию» создаёт зашифрованный файл.
«Отправить результаты на сайт» приостанавливает судейский ввод, готовит
подписанный возврат, передаёт его на Ubuntu и ждёт подтверждения всех записей
и пересчёта результатов. При ошибке он сохраняет данные и восстанавливает
локальный API. Никогда не выполняйте `docker compose down -v` вручную
для настоящего этапа.

После принятого ACK локальная база и секреты всё равно сохраняются,
пока администратор не подтвердит сверку. Полная физическая приёмка с
Ubuntu обязательна перед соревнованиями.

## 6. Следующий этап — одна база на весь сезон

Войдите в USD и выберите другой опубликованный этап. Нажмите «Загрузить этап» и подтвердите переключение. Программа скачает подписанный JSON и ключи.

Сохраняется возвратный файл предыдущего этапа, затем новый этап добавляется в ту же PostgreSQL и Docker-проект. Существующие участники, автомобили и версии конфигурации используются повторно, исторические регистрации и результаты не заменяются. Повторная загрузка того же пакета не сбрасывает судейские изменения. Изменённый пакет уже установленного этапа не применяется поверх результатов.

Если выбран ключ судей от другого этапа, мастер предложит выбрать правильный до изменения базы. Уже импортированный пакет можно продолжить устанавливать после истечения его срока: программа проверит исходную подпись и локальную квитанцию.

Синхронизация с Ubuntu перед новым этапом не требуется. Каждая папка `stage-workspaces/UUID` хранит свой исходный пакет и файлы возврата. Копии и отправка выбранного предыдущего этапа доступны в «Архиве этапов». Автоматическая отправка разрешена в течение 30 дней с подготовки исходного пакета; отправьте результаты до истечения этого срока.

Wi-Fi, IP и CA остаются прежними: телефоны повторно настраивать не нужно. Войдите заново обычным email/паролем USD. Если установка прервалась, нажмите «Продолжить загрузку» в окне USD. Старая папка больше не запускает судейство поверх выбранного нового этапа. Не удаляйте `.env`, `local-private`, исходную папку или Docker volumes.

Сохранённая база на ноутбуке не заменяет резервную копию на другом устройстве. Перед официальным этапом требуется физическая приёмка с роутером и двумя телефонами без интернета и проверка полученных данных на Ubuntu.


### Пакет этапа просрочен

Подписанный пакет можно впервые установить в течение 72 часов с выгрузки.
Проверьте дату и время Windows. При расхождении перезапустите Docker Desktop.
Если срок действительно истёк, скачайте в админке свежий пакет того же этапа
и ключ судей из этой же выгрузки. Запустите `USD-Install.cmd` в прежней папке:
мастер предложит выбрать оба файла. После уже выполненного импорта
установщик продолжает с исходным пакетом по записи в локальной базе.
