# USD — офлайн-сервер на Windows в три нажатия

Эта инструкция предназначена для **отдельного ноутбука Windows 10/11** с Docker Desktop (Linux containers / WSL2), подключённого к Wi-Fi-роутеру судей. Не выполняйте команды на центральной Ubuntu USD.

## Где кнопки

В папке `deploy/venue-lan/`:

| Значок | Что делает |
|---|---|
| **USD-Install.cmd** | Первоначальная установка: мастер создаёт отдельные ключи, подписанный этап, БД, медиахранилище, учётные записи ADMIN/судьи и запускает HTTPS |
| **USD-Offline.cmd** | Поднимает уже установленный LAN-сервер **из локально скачанных образов без интернета**, открывает локальный вход и включает автозапуск после входа в Windows |
| **USD-Online.cmd** | Отключает автозапуск локальной площадки, **останавливает контейнеры без удаления базы**, открывает `app.usd-russia.ru` |

Все команды выполняются через обычные двойные щелчки. **Для настоящего этапа кнопка «USD — Онлайн» автоматически передаёт подписанный журнал на Ubuntu, дожидается подтверждения и сохраняет резервную копию на ноутбуке.** Удалять Docker volumes, папку `local-private` или файл `.env` нельзя, пока результаты не сверены и не подтверждены центральным администратором.

## Первый запуск

1. Подключите ноутбук к выделенному судейскому Wi-Fi-роутеру. Отключите изоляцию клиентов (AP/client isolation), закрепите за ноутбуком постоянный приватный IP. Переведите сеть роутера в профиль **Частная / Private** Windows. Для первоначальной установки нужен интернет, чтобы скачать Docker-образы.
2. Откройте **Админка → Соревнования → Офлайн-сервер → Скачать для Windows**. Нажмите на архив правой кнопкой → «Извлечь всё». Откройте папку `USD-Offline-Windows`. Полный репозиторий скачивать не нужно. В архиве есть `INSTRUCTION.html`, которая открывается без интернета и печатается через Ctrl+P. Если Docker Desktop не установлен, мастер предложит установку через официальный `winget`; при первом запуске Docker потребуются принятие лицензионного соглашения, работающий WSL2 и, возможно, перезагрузка. Затем нажмите кнопку установки ещё раз.
3. Откройте двойным щелчком **`USD-Install.cmd`**. В окнах выберите Wi-Fi-адаптер и **ДЕМО** (рекомендуется для первой проверки) либо подписанный экспорт этапа. В реальном режиме выберите скачанные из админки файл этапа и открытый ключ через окна выбора файлов. Отпечаток скопируйте с защищённой страницы админки — его нельзя брать исключительно из скачанного пакета.
4. Подтвердите правило брандмауэра в Windows (UAC): разрешён только TCP 443 на указанном частном IP и только клиентам локальной подсети. Подтвердите импорт выбранного этапа кнопкой. Задайте в окнах пароли для локального `operator1@venue.invalid` (ADMIN) и `judge-01@venue.invalid` (судья). Это не настоящие email и не аккаунты публичного USD.
5. Мастер создаст `usd-venue` Compose с PostgreSQL18, RustFS, API, frontend и HTTPS/Caddy. Настройка RustFS создаёт **отдельный bucket** `usd-venue-media` и ограниченного пользователя, не передавая root-ключи запущенному API. Пароли автоматически генерируются криптографически стойким генератором Windows, хранятся в `.env` с ограниченным ACL и не публикуются в GitHub.

После этого открывается `https://IP-ноутбука/login`, а зрительское табло — `https://IP-ноутбука/venue/live`.

**Защита от несовпадения версий:** первый запуск до создания базы проверяет
два загруженных образа (API/frontend), SHA выпуска и наличие модулей
офлайн-сервера. Если онлайн Ubuntu ещё показывает старую версию, для <strong>настоящего этапа</strong> установщик
остановится с сообщением и НЕ начнёт работу на старом API. Для ДЕМО он может
взять строго закреплённый ранее проверенный SHA выпуска без доступа к живым данным. Не отключайте
проверку. После запуска мастер дополнительно сверяет точный SHA API и UUID
единственного этапа через локальное LIVE-табло.


**Если мастер остановился:** нажмите `USD-Install.cmd` ещё раз. Он продолжает сохранённые этапы настройки, **не удаляя тома** и не повторяя импорт после подтверждённого успеха. Если остановился после изменения БД, но до записи маркера, повторная операция может потребовать ручной проверки; мастер намеренно откажется «перезаписывать» существующие данные.

## Автозапуск и возвращение в интернет

После нажатия **`USD-Offline.cmd`** создаётся ярлык автозапуска **для текущего пользователя Windows**. После следующего входа пользователя в Windows ярлык запускает Docker Desktop (если он уже настроен) и Compose. Это **автозапуск при входе пользователя**, а не гарантированный запуск до входа в Windows или до разблокировки ноутбука.

После нажатия **`USD-Online.cmd`** в настоящем режиме сначала создаётся подписанный возвратный файл, автоматически отправляется на Ubuntu и проверяется точное подтверждение (ACK) базы и пересчитанных результатов. **Без подтверждения офлайн-сервер не отключается**, данные сохраняются. После подтверждения удаляется ярлык автозапуска и выполняется `docker compose stop` — **без `down -v` и очистки базы**. Для ДЕМО синхронизации с Ubuntu нет. Новый запуск `USD-Offline.cmd` возвращает локальный сервер с сохранённым состоянием.

## Доступ судей с iPhone/Android

В локальной сети открывается **та же админка USD**, но только с
разделами проведения соревнований: регистрация, инспекция, результаты,
участники и автомобили. Для настоящего этапа в админке заранее скачайте
**три файла**: подписанный JSON этапа (с зашифрованным доступом персонала),
отдельный ключ входа судей `.key` и публичный PEM проверки подписи.
Получение файлов: нажмите в админке <strong>«Скачать файл этапа»</strong>
для JSON, затем отдельно «Скачать ключ судей (.key)», затем
«Скачать открытый ключ» для PEM. Три отдельных нажатия надёжнее:
браузеры иногда запрещают несколько автоматических загрузок от одного клика.
Инсталлятор запросит все три файла через стандартные окна Windows и
перенесёт прежние UUID, email, пароли и ограниченные права сотрудников.
Отдельные новые аккаунты для настоящего этапа не создаются. Не храните
`.key` в общем чате, не распространяйте его вместе с JSON.
**Для ДЕМО** используются только локальные тестовые аккаунты.

Локальный HTTPS Caddy использует собственный CA. После успешного запуска мастер сохраняет публичный корневой сертификат в \`deploy/venue-lan/local-private/USD-Venue-CA.crt\`; это **не закрытый ключ**. **Один клик на ноутбуке не может автоматически установить доверие на чужом телефоне.** Каждый судейский телефон необходимо подключить к Wi-Fi площадки и **вручную** установить/доверить локальный корневой сертификат Caddy, предварительно проверив его отпечаток. На iPhone: открыть полученный доверенным способом профиль сертификата → «Настройки» → «Профиль загружен» → установить, затем «Основные» → «Об этом устройстве» → «Доверие сертификатам» → включить полное доверие для корневого CA. Не переносите закрытый ключ Caddy. На Android способ зависит от версии системы.

Откройте сайт по **IP ноутбука**, а не `app.usd-russia.ru`. При отключённом WAN два телефона будут работать с одним локальным API. LIVE-табло опрашивает API каждые 4 секунды.

## Что нельзя считать готовым

- **ДЕМО — только вымышленные участники.** Демо-данные нельзя выгружать на основную Ubuntu.
- Настоящие медиафайлы/полная история оборудования ещё не импортируются полноценно. Не проверяйте их как завершённый офлайн-функционал.
- Для настоящего этапа `USD-Online.cmd` автоматически переносит данные на центральный сервер. При конфликте программа не удаляет локальные данные и возвращает возможность работать офлайн.
- Нужно физическое испытание ноутбука, роутера и **двух телефонов с отключённым WAN**, с перезапуском Windows, проверкой доступа, инспекций, результатов, журналов и сохранности данных. До испытания не используйте сборку как официальный автономный судейский сервер.
