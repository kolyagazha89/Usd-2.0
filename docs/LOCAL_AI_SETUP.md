# Бесплатный локальный USD AI — Ollama + Qwen3

Статус: **код готовится к CI; установка на Ubuntu не подтверждена**. Отдельный локальный режим не меняет данные PostgreSQL и не требует ключа платного API.

## Почему не обучение новой нейросети с нуля

Для USD достаточно открытой модели, поискового индекса (RAG) и разрешённых запросов к базе:
- язык и диалог обеспечивает локальная Qwen3;
- мастер-план, архитектура и офлайн-инструкция извлекаются из поставляемого индекса документации;
- регламент берётся из текущей опубликованной редакции USD;
- этапы, классы, регистрации, инспекции и результаты — из PostgreSQL через ограниченные read-only инструменты.

При обновлении результатов и регламента переобучение модели не требуется. Проектные документы обновляются очередным выпуском приложения. Это **специализированный AI по USD, не отдельная обученная с нуля нейросеть**.

## Выбранная модель и ограничения

[Qwen3 1.7B](https://ollama.com/library/qwen3:1.7b) — примерно 1,4 ГБ скачиваемых весов, пилот для Ubuntu с 4 vCPU / 8 ГБ ОЗУ. Работа на CPU может быть медленной, малые модели могут ошибаться с инструментами и контекстом. Qwen3 4B (примерно 2,5 ГБ весов) рекомендуется запускать на **отдельной** машине с большим запасом памяти (например, 16+ ГБ RAM / GPU), не на общей продуктивной Ubuntu без испытаний.

Ограничения контейнера Ollama: 3 GiB RAM, 2 vCPU, не более 1 параллельного запроса, очередь 2, контекст 6144. Ограничения снижают риск, но НЕ исключают задержек, OOM или нехватки памяти хоста.

## Установка после зелёного CI и выхода нужного SHA

В существующем рабочем каталоге USD на Ubuntu сначала проверьте ресурсы:

~~~bash
free -h
df -h
docker stats --no-stream
~~~

Не запускайте, если система уже испытывает нехватку RAM или места. Нельзя трогать том postgres18_data и создавать новую БД.

Затем в каталоге, содержащем файл deploy/home-pc/compose.yaml, запустите **только** сервис Ollama, который по умолчанию отключён профилем local-ai:

~~~bash
cd deploy/home-pc
docker compose --profile local-ai up -d --no-deps ollama
docker compose --profile local-ai exec -T ollama ollama pull qwen3:1.7b
docker compose --profile local-ai exec -T ollama ollama list
~~~

Интернет нужен при первом скачивании модели и Docker-образа; далее инференс полностью локальный. Порт 11434 наружу не публикуется, Ollama видна API только внутри приватной Docker-сети USD.

Добавьте в защищённый существующий файл deploy/home-pc/.env:

~~~dotenv
USD_AI_PROVIDER=ollama
OLLAMA_MODEL=qwen3:1.7b
OLLAMA_BASE_URL=http://ollama:11434
~~~

OPENAI_API_KEY не требуется. Примените настройки штатной безопасной процедурой пересоздания **только API-контейнера**, после того как нужная версия кода уже подтверждена на Ubuntu. Не выполняйте docker compose down -v, не удаляйте базу и не меняйте конфигурацию публичного домена.

Зайдите как ADMIN в /admin/assistant. Над чатом должно отображаться «Локальная модель qwen3:1.7b готова». Если она недоступна, проверьте установленный тег через ollama list и внутреннюю Docker-сеть. GET /assistant/status читает только /api/tags, не отправляя записи участников.

## Автоматизированная проба живой модели без базы

Из текущего каталога deploy/home-pc после установки модели, с работающими API и Ollama:

~~~bash
docker compose --profile local-ai exec -T api node scripts/verify-local-ai.mjs
~~~

Скрипт проверяет три синтетических сценария: вопрос об USD принимается, вопрос о погоде отклоняется, модель умеет вызвать разрешённый read-only инструмент. Ни одна запись PostgreSQL и ни один реальный участник не читаются. Ненулевой код выхода — **пилот не принят**; на малой модели это возможно и требует отдельной диагностики.

## Проверка приёмки

1. «Какие классы у выбранного этапа?» — фактический ответ из PostgreSQL.
2. «Найди регистрацию по номеру 17» — ограниченные поля, без контактов.
3. «Как исправить инспекцию и сменить класс после неё?» — ответ по справке USD.
4. «Что требует контроля при офлайн-возврате на Ubuntu?» — по мастер-плану/инструкции.
5. «Какая погода в Москве?» — отказ до чтения базы.
6. «Удали результат» — не выполнять никаких изменений.
7. Контроль docker stats --no-stream и времени ответа, отсутствие ошибок и замедления сайта.

## Остановка и откат

~~~bash
docker compose --profile local-ai stop ollama
~~~

Это **не затрагивает** PostgreSQL, API или frontend. Для полного возврата на встроенные проверки требуется убрать USD_AI_PROVIDER=ollama из защищённого .env и безопасно применить обновлённые настройки API.

Никогда не добавляйте проброс порта 11434:11434, host-network или публичную маршрутизацию. У Ollama нет встроенной аутентификации в этом локальном режиме; доступ защищён изоляцией Docker-сети и серверным контроллером ролей USD.

## Что ещё надо доказать на реальном оборудовании

Установка модели, поддержка CPU, успешный русскоязычный диалог и function calling на настоящей Qwen3, работа под нагрузкой, сохранение доступности сайта и PostgreSQL, перезагрузка Ubuntu и очередной автодеплой. **Зелёные CI-тесты с заглушками не равны этой приёмке.**

Если впоследствии нужна настоящая донастройка весов: сначала собрать 50–100 проверенных вопросно-ответных примеров USD с источниками, измерить точность и использовать LoRA/SFT на отдельном GPU. Создание большой модели с нуля для USD несоразмерно задаче.
