# Подключение OpenAI для USD 2.0

## Что уже сделано

USD 2.0 использует серверный вызов OpenAI Responses API. Ключ хранится только на backend/Railway и не должен попадать во frontend, GitHub или браузер.

Переменные:

- OPENAI_API_KEY — секретный API-ключ OpenAI.
- OPENAI_MODEL — необязательная модель; по умолчанию используется `gpt-6-astra`.

Ассистент передаёт модели актуальный контекст USD 2.0: участники, автомобили, регистрации, результаты, этапы, импорты, исторические результаты, дисквалификации и качество данных.

## 1. Создать API-ключ

Откройте страницу API Keys в OpenAI Platform и создайте отдельный ключ для USD 2.0.

Рекомендуется создавать отдельный project API key для production и задать срок действия/ротацию ключа.

ВАЖНО: полный секретный ключ показывается при создании. Если ключ потерян, нужно создать новый.

## 2. Пополнить API billing

Подписка ChatGPT и API оплачиваются отдельно. Для платного API нужно настроить billing API и иметь доступный баланс/лимит.

Для production удобно использовать prepaid credits и, при необходимости, автоматическое пополнение с месячным ограничением.

## 3. Добавить ключ в Railway

Откройте проект USD 2.0 в Railway:

Project → Environment: production → Service: usd-api → Variables

Добавьте:

OPENAI_API_KEY = ваш секретный ключ

Не добавляйте ключ во frontend и не коммитьте его в .env, если файл попадает в Git.

Дополнительно можно задать:

OPENAI_MODEL = gpt-6-astra

После сохранения Railway должен пересобрать/redeploy сервис.

## 4. Проверка

После успешного deploy:

1. Войдите в админку USD 2.0.
2. Откройте «Ассистент».
3. Напишите:
   «Проверь качество данных».
4. Затем:
   «Покажи состояние системы».
5. Затем:
   «Проверь готовность текущего этапа».

Если ключ подключён, ответы будут формироваться моделью OpenAI. Если ключ отсутствует или API временно недоступен, backend использует встроенные безопасные диагностические функции там, где они поддерживаются.

## 5. Безопасность

Никогда не вставляйте OPENAI_API_KEY:

- в React/Vite код;
- в localStorage;
- в HTML;
- в GitHub;
- в сообщения ассистента;
- в скриншоты;
- в публичные переменные VITE_*.

Ключ должен находиться только на сервере.

Для production рекомендуется отдельный project key, срок действия и регулярная ротация.

## 6. Стоимость

Расход зависит от выбранной модели и количества входных/выходных токенов. Ассистент USD ограничивает размер ответа и передаваемого контекста, чтобы не делать бесконтрольные запросы.

Рекомендуется также установить spend limit/alerts в OpenAI Platform.

## 7. Важное ограничение текущей версии

OpenAI уже подключён как интеллект ассистента, но OpenAI сам по себе не получает доступ к GitHub или production shell USD 2.0.

Запросы на изменение кода проходят через защищённую очередь ассистента с подтверждением. Полноценное автоматическое применение изменений к GitHub/PR должно быть подключено отдельным безопасным executor-модулем; запуск произвольных shell-команд из админки не используется.

## Быстрый вариант для Windows PowerShell

Для локальной разработки официальный OpenAI quickstart допускает:

`setx OPENAI_API_KEY "ваш_ключ"`

После этого нужно открыть новый PowerShell.

Для Railway локальная переменная не нужна — ключ добавляется непосредственно в Variables сервиса `usd-api`.
