# Ассистент USD — возможности и подключение AI

## Что делает сейчас

Раздел `/admin/assistant` доступен только администрации с соответствующими правами. Ассистент разделяет ответы по **проверенной базе USD**, **инструкции** и **AI-модели**.

Работают без OpenAI API:

- сводка по активным участникам, автомобилям, регистрациям, этапам и результатам;
- контроль качества данных с конкретными типами проблем и переходом к нужным экранам;
- диагностика незавершённых импортов;
- готовность выбранного этапа (активные классы, регистрации, допуски, отказы, ожидающие инспекции, результаты);
- инструкция по изменению классов и отдельным номерам BassRace при судействе.

При наличии OpenAI API работает свободный диалог с учётом последних восьми сообщений. История отправляется из текущего интерфейса (не сохраняется в отдельную таблицу сообщений). Контекст модели — только агрегированная сводка из USD, а не полная выборка участников/телефонов/почты. Для проверки конкретных записей используйте профильные страницы.

**Важно:** ассистент ничего не редактирует в базе через свободный текст. Ранее автоматически создаваемые запросы «изменить код» не имели подключённого исполнителя, поэтому их создание из чата отключено. Текущая очередь запросов сохранена для совместимости, но не является GitHub-исполнителем. Не воспринимайте подтверждение такого запроса как выполненный PR.

## Настройка API на Ubuntu

OpenAI вызывается только сервером `api` через Responses API. Секрет не помещается в frontend, Git, локальное хранилище или ответы ассистента.

В защищённом файле `deploy/home-pc/.env` для `usd-home` задаются:

- `OPENAI_API_KEY` — отдельный production API key с лимитом расходов;
- `OPENAI_MODEL` — необязательно, по умолчанию `gpt-4.1-mini`.

В `deploy/home-pc/compose.yaml` сервис `api` уже читает `env_file: .env`. После настройки переменных пересоздайте **только** API в рамках штатной процедуры развёртывания, не трогая БД или образы других сервисов. Убедитесь, что контейнер получил новую конфигурацию, не выводя сам секрет.

Подписка ChatGPT не включает оплату API. Требуется доступный баланс и корректные права API-ключа для выбранной модели.

## Проверка приёмки

1. Войдите с ролью ADMIN, откройте «Ассистент USD».
2. Выберите конкретный этап. Спросите «Проверь готовность этапа» и сравните счётчики с регистрациями и инспекциями.
3. Нажмите «Что сейчас требует внимания?» и «Разбери последний импорт»: должны появиться проверяемые цифры и переходы в админку.
4. Спросите «Как судье изменить класс и добавить BassRace?» — должна появиться инструкция, но данные не должны измениться.
5. Напишите «Измени дату этапа» — ассистент обязан **отказаться от прямой записи** и отправить в соответствующий раздел, без фиктивной задачи и подтверждения.
6. Спросите произвольный вопрос дважды, во втором сообщении сошлитесь на первый. Если ключ подключён и API доступен, модель получит ограниченную историю чата. Иначе честно увидите сообщение о недоступности AI.

Не выводите API-ключи, персональные данные или токены в тестовых запросах и логах. Проверки через UI и CI не заменяют отдельную приёмку на Ubuntu.

## Технические ограничения

- Запросы AI имеют таймаут 22 секунды, ограничение длины текста и ответа.
- Сообщения с ролями `system`/`developer` из браузера игнорируются.
- Автоматического исполнения SQL, команд сервера, изменений GitHub/PR из чата **нет**.
- Роль `ADMIN` и разрешения модуля `assistant` по-прежнему обязательны.
