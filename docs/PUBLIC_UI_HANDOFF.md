## Продолжение

- Сохранён выбранный графитовый/красный USD-дизайн, оригинальный логотип и светлая админка.
- Добавлены активные пункты мобильной публичной панели и вложенных страниц верхнего меню.
- Автомобиль и конфигурации сохраняют навигацию ЛК; «Открыть конфигуратор» ведёт сразу к конфигурациям.
- Шапка участника адаптируется одной строкой; обновление и выход имеют отдельные классы и доступные названия.
- Уплотнены заголовки и карточка авто в редакторе, убран повторный заголовок направления и отдельный фон вложенной страницы.
- Высота cookie-баннера измеряется при переносе текста/изменении окна. Резерв прокрутки и кнопка сохранения учитывают баннер и нижнюю панель. Баннер скрыт на время выбора оборудования и диалогов конфигуратора.
- Исправлено существовавшее до этих изменений переполнение карточек админской панели на 320px (2px); тема админки сохранена.

Дополнительно: семь вкладок редактора, поиск модели, отказ добавления отсутствующей модели, добавление оборудования из каталога в локальный черновик, шапка одной строкой, активные пункты, отсутствие перекрытия навигации/сохранения баннером. Не объединять устаревшие draft PR #284/#285 автоматически. PR #232, импорт и инфраструктурный перенос остаются отдельными задачами.

## Кабинет участника — структурная переработка

Основа пакета: main `5e84b525` (PR #289). Источник визуальной системы — три пользовательских PNG-экспорта Figma от 21 октября: `USD — Premium Vehicle Configuration · UI concept(1).png`, `(1)(1).png`, `(2)(1).png`. Исходный Figma MCP ограничен тарифным лимитом. Экспорты показывают конфигуратор; кабинет и пошаговая регистрация адаптируют их систему, а не объявляются точной копией отсутствующего отдельного фрейма.

- `frontend/src/participant/MemberDashboard.tsx`: новый обзор «Мой USD»: ближайший старт и заявка/QR, карточка участника, автомобиль/направления, последние результаты. Удалены прежние повторные блоки статистики. Подготовка из трёх шагов показывается только до сохранения оборудования.
- `ParticipantIntro.tsx`: отдельный заголовок и короткое описание каждого раздела.
- `RegistrationFlow.tsx`: три экрана «Автомобиль → Классы → Подтверждение», доступность продолжения, сохранение выбора при возврате, доступный фокус. Запросы и проверки допуска остаются в `App.tsx`.
- `member-experience.css`: единая участническая система поверх существующих тем — нейтральный чёрный/графит, Arial/Helvetica, ровный красный акцент, общий ритм карточек/контролов; административная оболочка исключена из селекторов.
- Оборудование участника выводится компактными карточками с раскрытием параметров; контролируемые поля, индексы, удаление и очистка связей усилителей сохранены. Админские строки не сворачиваются.
- После сохранения профиля участник остаётся в форме. Подтверждение исчезает при новом изменении, включая видимость профиля.
- Карточки заявок используют всю ширину на телефоне; отмена вынесена во вторичное действие. Отменённая заявка не предлагает недоступный QR.
- Кабинет учитывает регистрацию каждого автомобиля на конкретный этап: при полной регистрации открывает существующую заявку; для второго автомобиля сохраняет отдельное действие.
- Защита от запоздавшего ответа оборудования: выбор другого автомобиля не заменяется результатом предыдущего запроса.

Проверки: 35 frontend tests, включая три шага с отправкой в изолированный API, точный payload, возврат назад, согласия, многомашинную доступность и гонку запросов. Production build проходит. Браузерный прогон проверяет собранные JS/CSS, 320/390/1024/1440 px, семь разделов редактора, раскрытие/изменение количества, каталог и короткую высоту 568 px. Реальные заявки и пользовательские данные не создаются. Native Safari и сохранение на реальном аккаунте не подтверждены.
