# CSS audit — admin mobile and public surfaces (2026-10-31)

## Confirmed defect and repair

The stylesheet import order in `frontend/src/main.tsx` is:
`styles.css`, `participant-ui-polish.css`, `ui-consistency.css`,
`premium-ui.css`, `public/premium-base.css`, `public/premium-public.css`,
`public/premium-member.css`, `public/premium-configurator.css`,
`participant/member-experience.css`, and finally `dark-velocity-sitewide.css`.

The last file previously set `body .app-shell .sidebar .nav-item.active`
to a white gradient with `!important`, overriding the dark active-state
rule in `ui-consistency.css`. This is the confirmed reason the sidebar
regressed after the earlier mobile fix. The final stylesheet now preserves
its dark state and explicitly enforces full-width mobile admin layout.

## Audit observations / remaining risks

- Multiple CSS layers style `.sidebar`, `.main`, `.content`, and
  `.nav-item.active`; the last-loaded stylesheet wins at equal or greater
  specificity. The final theme must not silently undo shared responsive rules.
- `ui-consistency.css` contains shared controls, participant uploads,
  registration UI, and mobile admin rules. Its responsibility is broad;
  future refactoring should separate components by ownership, without
  changing all selectors in a single untested release.
- The main `styles.css` is very large. Avoid adding more global rules there;
  new rules should be scoped to a specific page/root component.
- CSS tests detect known regressions but **do not** replace iPhone Safari
  screenshots and real-device checks for inspection/registration pages.
- Missing logos and historical participant/car photos are **not proven to be
  CSS bugs**. Verify API response codes, completed media rows, S3 object keys,
  and settings URLs independently; do not modify or reset production data.

## Required review checklist for every new CSS change

1. Search existing selectors in **all imported stylesheets**, including files
   loaded after the target stylesheet. Inspect specificity and `!important`.
2. Prefer modifying the existing owning rule; do not append a duplicate
   global override to an unrelated file.
3. Scope styles under `.app-shell`, `.usd-live`, or `.usd-member`
   as appropriate; ensure admin light theme stays distinct from public dark.
4. Check 320, 375, 390, 430, 768, and desktop widths; confirm there is no
   document-level horizontal scroll or iOS input-focus zoom.
5. Add or update a regression test for the selector/behavior and run frontend
   tests/build. Inspect the **computed** style in a browser, not only source.
6. Require GitHub CI and actual prerelease QA before merge. Never assume a
   successful Docker release means visual correctness.
