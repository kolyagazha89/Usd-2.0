## До применения

1. Сохранить оригиналы и ключ в раздельном закрытом хранилище, в том числе на утверждённом втором диске; проверить восстановление/права/неизменяемость. Не считать same-host копию независимым бэкапом.
2. Инвентаризировать активные ветки, теги, PR refs, форки и зеркала, runner/deployer checkout, SHA-политики, GHCR references. Подготовить окно координации, защищённую приватную копию refs и сверку всех remote refs перед заменой.
3. Получить отдельное согласование history rewrite/force-update. Обычный PR удаления файла не удаляет старые blobs; не выполнять слепой push --mirror. Запретить повторную публикацию старой истории из клонов.
4. Заменить только согласованные heads/tags с проверкой прежних SHA. PR refs и недостижимые cached blobs требуют обращения к GitHub Support; old-SHA raw может продолжать работать после замены веток. Не обещать удаления уже скачанных копий.
5. Проверить анонимно старый raw URL, новые reachable refs, release artifacts. Выполнить CI и отдельно согласованный безопасный предрелизный rollout; схема/данные production не изменяются этой процедурой.
6. Не закрывать #427 до фактической проверки публичного доступа и сохранности приватного оригинала.
