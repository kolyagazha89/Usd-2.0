# USD — безопасная приёмка релиза на Ubuntu

Цель: выпустить обновление только на `app.usd-russia.ru`. **Не менять** `usd-russia.ru`, не очищать PostgreSQL и не запускать исторический импорт повторно.

## 1. Проверка без изменений

После слияния и публикации образов на самом Ubuntu-хосте:

```bash
cd /home/usd/usd-deploy
git fetch origin main
git checkout main
git pull --ff-only origin main
sudo python3 deploy/home-pc/release-readiness.py --live
sudo python3 deploy/home-pc/release-readiness.py --live --json
```

Результат `NOT READY` означает **стоп**, а не разрешение автоматически отключать защитные политики. Отчёт не раскрывает содержимое `.env` и конфигураций резервного копирования. Он проверяет только наличие и структуру предусловий, **не заменяет** реальную проверку восстановления БД и медиа.

## 2. Проверка GitHub

Перед релизом зафиксировать конкретный полный SHA `main` и убедиться, что для него завершились успешно: Backend CI, Frontend CI (если менялся фронтенд), Home PC deployment safety checks, Competition journey и Public browser QA. Проверить, что опубликованы оба OCI-образа `api` и `frontend` с совпадающей меткой `org.opencontainers.image.revision`.

## 3. Резервное копирование и миграции

Не запускать автоматический релиз, если нет проверенной **независимой** копии PostgreSQL и S3/медиа, доступной вне хоста, и успешного восстановления на временное хранилище. Если дерево `backend/prisma` отличается от одобренного, автоматический деплой должен остановиться: миграции допускаются только после отдельной репетиции на восстановленном дампе и явного одобрения оператора.

## 4. Выпуск

Только после всех проверок и подтверждения доступности хоста — использовать уже предусмотренный `usd-auto-deploy.service` с одобренными политиками. Не переписывать `.env` вручную и не подменять SHA тегом `latest`. Если политика запрещает выпуск, устранять причину и повторять проверки, а не обходить её.

## 5. Приёмка

Проверить `https://app.usd-russia.ru/usd-release.json` и `https://api.usd-russia.ru/release`: обе ревизии должны совпадать с целевым SHA. Проверить вход и выход, смену пароля, личный кабинет участника, конфигурацию автомобиля, регистрацию на этап, инспекцию, ввод результатов, записи и права администратора/судьи, мобильные экраны 320/390 px, изображения и загрузку медиа. Убедиться, что основная публичная площадка `usd-russia.ru` не менялась.

## 6. Стоп/откат

При несовпадении ревизий, ошибках API, падении smoke-тестов, проблемах с БД или недоступности критических функций **остановить продвижение**. Использовать существующий механизм отката контейнеров только после проверки совместимости схемы. Не восстанавливать дамп поверх живой БД без отдельного решения оператора.

Это инструкция для оператора, **не свидетельство** выполнения проверки на реальном сервере.
