# USD — приёмка онлайн-релиза владельцем (10 ноября 2026)

> **Назначение:** выполнять на реальных устройствах, записывать фактический результат; это не доказательство готовности по умолчанию. **Ноутбук + роутер + локальный офлайн-сервер отложены и в этот чек-лист не входят.** Работа судей на площадке проверяется при доступном API. Основной `usd-russia.ru` не менять.
>
> **На 09.11.2026:** последняя сверенная ревизия GitHub `main` и обоих публичных контейнеров — `942f5d9c6f7c418a9d3c2ea7fe602f184aca51fa`. Все основные GitHub Actions, включая Public browser QA и deploy request, были успешно завершены для этой ревизии. Это не заменяет ручную проверку ADMIN/JUDGE и iPhone PWA.
>
> **Источники:** `docs/USD_MASTER_PLAN.md`; `docs/UBUNTU_RELEASE_ACCEPTANCE.md`; issues #114, #409, #438, #442, #446, #454, #427.

## 0. Правила безопасного испытания

1. Использовать только **https://app.usd-russia.ru** (предрелиз) и **https://api.usd-russia.ru**; не менять основной домен.
2. Подготовить три раздельных тестовых аккаунта/сеанса: ADMIN, JUDGE с только нужными правами и обычный участник. Отдельно открыть гостя в приватном окне. Для писем и PUSH нужен собственный адрес и добровольно подписанный телефон.
3. Составить тестовую карточку **«ПРОВЕРКА USD / 10.11»** и использовать **тестовый этап** с безопасными настройками и понятным владельцу списком будущих удаляемых тестовых записей. Не переписывать архивные результаты, номера, рекорды, участников или реальные платежи ради теста.
4. Для каждого теста указать **ОК / ОШИБКА / НЕ ПРОВЕРЕНО**, устройство/браузер, время, тестовый этап, скриншот и ожидаемый/фактический результат. Не отправлять пароли, JWT, приватные телефоны и персональные данные в публичный GitHub issue.
5. Ошибка класса **P0** (нельзя зарегистрировать/судить, потеря данных, перепутанные номера, доступ к чужому профилю, 500 API, неверная публикация результата или неподтверждённый релиз) блокирует выпуск. **P1** — сломанный сценарий, форма/адаптивность или уведомление, если есть безопасный обход. **P2** — косметика. Не объявлять весь проект завершённым при открытом P0.
6. Не запускать `prisma migrate reset`, удаление/перезапись БД, физическое удаление связанных исторических строк, массовый импорт без dry-run, отключение gate или полный production reset. Для проверки восстановления использовать **только отдельную временную БД** с администратором Ubuntu.

## 1. Технические ворота: сначала сравнить ревизии

- [ ] Открыть [frontend release](https://app.usd-russia.ru/usd-release.json) и [API release](https://api.usd-russia.ru/release). Оба HTTP 200, `revision` совпадает между ними и с **текущим полным SHA GitHub main**; не просто «контейнеры Up».
- [ ] Проверить [GitHub Actions](https://github.com/kolyagazha89/Usd-2.0/actions) для *этого SHA*: Backend CI, Frontend CI, Web push PostgreSQL 18, Competition journey, Home PC deployment safety, Public browser QA, Publish images, Request USD home-PC deploy — успешно. Если SHA стал новым, повторить сравнение.
- [ ] С компьютера в каталоге репозитория по желанию выполнить **безопасную команду только чтения**: `node scripts/online-release-preflight.mjs <ПОЛНЫЙ_SHA_MAIN>`. Все проверки `ok:true`; ни один endpoint не требует передачи пароля; команда не меняет сервер.
- [ ] При наличии доступа к Ubuntu оператор запускает **только чтение** `sudo python3 deploy/home-pc/release-readiness.py --live`; проверяет disk/RAM/Docker/Caddy/RustFS/backup. Автоматические зелёные проверки CI не удостоверяют отдельный HDD и восстановление.
- [ ] Убедиться, что `usd-russia.ru` не переключён на предрелиз и исторические строки/фотографии не исчезли.
- [ ] Записать SHA, дату и время, URL, результат каждого CI, номер последнего действительно ACCEPTED деплоя, идентификатор и дату проверенного бэкапа.

## 2. Публичный сайт (гость, 390 и 1440 px)

- [ ] **Главная:** логотип/шапка не сдвигаются после загрузки; нет чёрных несогласованных прямоугольников, горизонтального скролла и случайной белой полосы. Доступно меню и нижняя навигация.
- [ ] **Результаты:** главная показывает корректные карточки, класс, ФИО, единицу дБ/м/с, фото при наличии; [все результаты](https://app.usd-russia.ru/results) открываются, фильтры/перелистывание работают.
- [ ] **Рекорды:** [страница](https://app.usd-russia.ru/records) показывает реальный максимальный показатель и участника; BassRace не входит в рекорды; публичное фото не превращается в инициалы при наличии доступного фото.
- [ ] **Этапы:** [список](https://app.usd-russia.ru/stages) и карточка этапа корректны; афиша показывается целиком по заданным пропорциям; дата, адрес, открыта/закрыта регистрация согласованы.
- [ ] **Партнёры:** [каталог](https://app.usd-russia.ru/partners) показывает категории, включая студии. Обычные партнёры и студии идут одинаковыми карточками в **одной колонке**; длинный текст «Читать далее → Свернуть» работает. Логотип не обрезан, индивидуальная настройка пропорций сохранена.
- [ ] **Главная, карусели:** обычные и студии автоматически движутся, доступны нативные свайпы; во время наведения/focus пауза, после ухода продолжение, осознанный ручной свайп не «борется» с авто. На странице каталога карусели нет.
- [ ] **Новости/правила/юридические:** фотографии целиком, документы открываются, нет битых ссылок; [правила](https://app.usd-russia.ru/rules), приватность и согласия читаемы с телефона.
- [ ] Сеть: обновить страницу по прямому URL `/partners`, `/rules`, `/stages` и `/records`; не должно быть 404 SPA или пустых бессмысленных экранов.
- [ ] Консоль браузера без критических ошибок, изображения и JSON API отвечают 200, случайных сетевых 500/timeout нет. Отдельно контролировать `/records/current` и stage-poster SITE_ASSET (issue #424).

## 3. Участник: профиль, машина, каталог

- [ ] Создать отдельного **тестового** участника и войти; письмо подтверждения поступает; после подтверждения личный кабинет открывается.
- [ ] Поиск исторического профиля: ввести существующий тестовый ФИО; показать выбор профиля и безопасную заявку, если email не совпадает. Кнопка **«Ранее не участвовал — создать новый профиль»** доступна без ввода ФИО.
- [ ] В ЛК обновить имя/город/телефон с корректной валидацией; выйти/зайти повторно и убедиться, что данные сохранились. В соседнем аккаунте они не отображаются.
- [ ] Создать автомобиль: марку и модель выбрать из **реального каталога**; произвольная несуществующая пара должна отвергаться и клиентом, и API. Повторить в админке; старую историческую марку можно оставлять без скрытой подмены.
- [ ] Проверить российский госномер, в том числе **регион 181**, и некорректный формат. В iPhone используется штатная клавиатура; ввод не ломает фокус/масштаб. Чужой дублирующий номер не должен создать вторую машину.
- [ ] Загрузить тестовую фотографию автомобиля и участника, обновить страницу: фото должно быть видно, а не только запись о файле в медиатеке.
- [ ] Конфигурация: пройти фронт/бас/тыл/усилители/питание/магнитолу; поиск только по активным брендам/моделям; обязательный SUB для SPL/BassRace/Storm Wall, FRONT для BFSPL, REAR для BDW. Новая версия не переписывает старую.

## 4. Регистрация — онлайн и въезд (P0)

- [ ] Под участником открыть будущий тестовый этап: маршрут **машина → конфигурация → классы → подтверждение**. Смена машины сбрасывает устаревшее подтверждение конфигурации.
- [ ] Обычные классы — не более **5 на основном номере**. BassRace может добавляться сверх пяти на **новых номерах**; проверить 5 обычных + 4 BassRace в тестовом окружении, если созданы нужные независимые направления.
- [ ] Завершить регистрацию; увидеть страницу **«Регистрация успешно сохранена»**, ФИО/машину/этап/классы, все стартовые номера, QR-код и USD ID. Сохранить QR-скриншот или SVG. Фраза «оплата подтверждена» не должна возникать без подтверждения.
- [ ] Судья/ADMIN: открыть `/admin/event-day` или `/admin/inspections`, найти человека по ФИО/номеру/госномеру; при отсутствии истории создать участника **на въезде** с ФИО + машина + валидный номер и согласиями, **без обязательного списка аппаратуры**.
- [ ] Участник с уже существующим профилем добавляет **новую машину** на въезде, не создавая дубль аккаунта. Система предупреждает о совпадающем госномере.
- [ ] Отменить **тестовую** регистрацию и подтвердить освобождение её номеров; новые тестовые регистрации могут занять освободившиеся номера. Реальные выступления не удалять.
- [ ] После завершённого тестового этапа с неполной конфигурацией новую заявку на следующий этап система блокирует, но результат прошлого этапа остаётся доступным. После документального заполнения конфигурации ограничение снимается без перезаписи исторического снимка.

## 5. Инспекция и судейство (P0)

- [ ] Судья входит своей ролью; видит только разрешённые модули, не полную ADMIN-панель.
- [ ] Просканировать QR из тестового пропуска камерой **вошедшего судьи**. Открывается именно нужная регистрация. При открытии QR гостем не выдаётся возможность менять инспекцию.
- [ ] Отметить **PASSED**; статус сохраняется и виден в карточке регистрации.
- [ ] Попробовать **FAILED** без текста: сохранение запрещено. С осмысленным комментарием — возможно, причина видна администратору.
- [ ] Исправить выбранные классы после инспекции; не допускается незаметное перемещение класса на другой номер при существующем результате. Удалённые BassRace классы освобождают только ненужные дополнительные номера.
- [ ] Внести тестовый результат через роль судьи, проверить класс, номер, величину и единицу; после перезагрузки результат остался. Удаление/редактирование результата требует ADMIN.
- [ ] Проверить явную публикацию результатов: закрытые результаты не видны гостю, опубликованные — видны в правильном этапе, направлении и классе. Не публиковать настоящие неопубликованные протоколы ради теста.

## 6. Справочники и административная панель

- [ ] `/admin/vehicle-catalog`: поиск марки/модели, фильтры, отключение, включение, редактирование, «Включить все» по указанной области. Отдельно проверить дубль при повторном импорте.
- [ ] `/admin/components`: категории → бренд → модель; поиск, изменение, архивирование, удаление **только неиспользуемых**, массовое включение; предпросмотр CSV; запрос на отсутствующую модель попадает в очередь.
- [ ] `/admin/partners`: отдельно настроить пропорции логотипа для каждой категории и проверить предпросмотр; после сохранения посмотреть главную/каталог на 390 и 1440 px.
- [ ] `/admin/news`: фото по реальному формату целиком, редактирование/публикация; `/admin/rules`, `/admin/site-settings`, `/admin/media`: изменения сохраняются без HTTP 500. Для теста использовать обратимую правку и восстановить исходную.
- [ ] `/admin/profile-links`: заявка чужого аккаунта не присваивает профиль автоматически; ADMIN видит конфликт, dry-run объединения и данные о связанных регистрациях, не потеряв результаты/рекорды. **Не объединять реальные профили без отдельного бэкапа.**
- [ ] `/admin/inbox`: колокольчик и счётчик; «Не просмотрено/Просмотрено/Выполнено» работают; выполнение не подменяет утверждение самой заявки. Проверить два аккаунта ADMIN отдельно.
- [ ] `/admin/teams` и [публичные команды](https://app.usd-russia.ru/teams): заявки в команду, состав, результаты по этапам и сезонам; учитывать команду **на момент инспекции**, а не сегодняшний состав; не придумывать баллы или выручку.
- [ ] `/admin/stage-report` и `/admin/season-report`: итоги классов сгруппированы по направлениям; сравнение сезонов показывает «не сопоставимы» для переименованных классов; **«Печать / PDF»** выдаёт читаемый A4 без меню ADMIN и обрезанных таблиц.
- [ ] Журнал email, тестирование писем, настройки уведомлений и аудит действий доступны по ролям; тестовые письма доходят, тексты релизные.

## 7. iPhone Safari / установленное PWA (P0 для UX)

- [ ] На настоящем iPhone открыть Safari, затем через «Поделиться → На экран „Домой“» установить USD. В обычном Safari и PWA сравнить шапки и нижнюю панель.
- [ ] На коротком экране **«Загружаем данные»** с медленной сетью нижняя панель **с первого кадра** прижата ко дну и не поднимается/опускается после загрузки. Сделать запись экрана от запуска до готового ЛК.
- [ ] Проверить скролл вверх/вниз, скрытие адресной строки, поворот портрет/альбом, открытие клавиатуры госномера, отступы от «чёлки» и нижней полоски Home Indicator. Ни один элемент не находится под безопасной зоной.
- [ ] Публичный и личный кабинеты при ширинах 320/390/768/1440: без горизонтального скролла, искажения фоток, обрезанных кнопок и всплывающих окон за краями.
- [ ] Прямой запуск PWA открывает главную/ожидаемый маршрут, не принудительно чужой профиль; обновление профиля и QR не ломает верх/низ.

## 8. PUSH, email, безопасность и данные

- [ ] ADMIN с добровольно включёнными PUSH получает **один** тестовый сигнал о новой заявке на комплектующую/привязку; текст не раскрывает ФИО/email и не дублируется. На устройстве без согласия PUSH не отправляется.
- [ ] Участник получает необходимое письмо (подтверждение/восстановление) на свой тестовый email; письмо оформлено в стиле USD и ссылка ведёт на предрелиз. Проверить флаг согласия на рассылку.
- [ ] Участник/гость при прямом переходе в `/admin` и ADMIN API не получает доступ. Судья не может удалять результаты или управлять ролями, если не выданы специальные права.
- [ ] Запрос с чужого тестового аккаунта не раскрывает фото/телефон/машину в приватном режиме; старые архивные email нельзя выкладывать в отчёты и GitHub (issue #427).
- [ ] Реальное восстановление PostgreSQL 18 **и медиа** из подписанной/проверенной копии на изолированном хранилище проводит оператор Ubuntu; наличие backup-файла без восстановленного теста — **НЕ ОК**.
- [ ] После ручных тестов пересмотреть последние логи, HTTP 500/502/timeout, ёмкость дисков, RustFS, PostgreSQL, сертификат HTTPS, таймер деплоя и откат. При P0 не переключать основной домен.

## 9. Решение о выпуске

**GO** только если все P0 — ОК, критические P1 закрыты или документирован согласованный безопасный обход, нет потерь исторических данных, реальный iPhone проверен, обе публичные версии совпадают с одобренным `main`, восстановление проверено оператором и нет запрещённых межролевых доступов.

**NO-GO**, если несовпадение SHA, нет работоспособных регистраций/судейства, неправильные номера BassRace, 500/timeout на критических API, сломанная нижняя панель в реальном PWA, потеря фото/истории/входа, утечка персональных данных или неподтверждённый backup/rollback.

```
Дата и местное время:
URL и раздел:
Как воспроизвести (1, 2, 3):
Ожидалось:
Получилось:
Скриншот/видео без чужих персональных данных:
SHA фронтенда/API:
Статус: ОТКРЫТ / ИСПРАВЛЕН В PR / DEPLOYED / ПРОВЕРЕН ВРУЧНУЮ
```

### Протокол приёмки

- Дата: ___________  Ответственный: ___________
- SHA `main`: ___________________________________________
- SHA `frontend`: _______________________________________
- SHA `API`: ___________________________________________
- Все обязательные CI: ОК / НЕТ; Ubuntu проверена: ДА / НЕТ
- P0: всего ____; пройдено ____; ошибки ____; не проверено ____
- P1: всего ____; пройдено ____; ошибки ____; не проверено ____
- Проверка на настоящем iPhone/PWA: ОК / ОШИБКА / НЕ ПРОВЕРЕНО
- Резервная копия + тест восстановления: ОК / ОШИБКА / НЕ ПРОВЕРЕНО
- Итог: **GO / NO-GO**. Подпись/комментарий: _______________________

> **Важно:** это чек-лист онлайн-релиза. Полноценная автономная работа судей при отключённом интернете, локальный сервер на ноутбуке и синхронизация через роутер остаются в отложенном backlog и не должны проверяться как готовые функции.
