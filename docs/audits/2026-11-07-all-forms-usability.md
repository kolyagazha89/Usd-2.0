# USD · Сквозной аудит форм и пошаговых сценариев · 07.11.2026

Задача: #454, USD_MASTER_PLAN §14. Область: публичный сайт, кабинет, команды, судейство, регистрация на площадке, светлая админка. Релизный PR: #458. Основной домен `usd-russia.ru` не меняется.

## Метод проверки

- В репозитории 86 TSX-компонентов интерфейса (снимок дерева на момент анализа); `frontend/scripts/audit-form-controls.mjs` обходит **все** TSX в `frontend/src`, считает нативные `form/input/select/textarea` и возвращает файлы/строки потенциально неподписанных полей. Проверяются вложенные `label`, `htmlFor/id`, `aria-label`, `aria-labelledby`; `placeholder` не считается доступным названием. Утилита **не** утверждает, что динамические составные поля доступны без браузерной проверки. `--json` — машинный список, `--strict` — режим для ручного исправления накопившихся предупреждений.
- Контракты форм и ограничения сверены с реализацией, тестами, RBAC и UX-требованиями (каталоги, BassRace, исторические данные). `frontend/test/audit-form-controls.test.mjs` заставляет CI сканировать все исходники, а не отдельные фикстуры.
- Выявлены места, где шаг, проверка, сохранение или ошибочный повтор могли привести к тупику, дублированию либо неправильному действию судьи. Исправления по приоритету P1 реализованы внутри **одного** PR #458.
- Полный end-to-end аудит с реальным ADMIN, судьёй, участником, медиа RustFS и мобильными устройствами возможен только после выкладки в Ubuntu. CI и статический скан не заменяют эту проверку.

## Общие требования и исправления PR #458

1. Разделение длинных форм на логические шаги; навигация названа и доступна с клавиатуры. У формы есть статус и финальная проверка перед записью. Короткие операции не дробятся.
2. При переходах между экранами редактируемые значения остаются в React-состоянии, без случайного сброса. Скрытые панели не должны становиться видимыми из-за CSS `display:grid`.
3. Мобильные кнопки не меньше 44px, адаптивные поля и итоговые карточки, видимый `:focus-visible`, никакого принудительного кастомного экранного ввода госномеров.
4. При сбое ответа после успешного создания регистрации не предлагать дублировать POST; сохранённый ID используется для безопасного повторного открытия.
5. В `SearchableSelect` выбор на сенсорном устройстве выполняется до `blur`; значения по-прежнему берутся только из списка.
6. Пароли и секреты не попадают в итоговый обзор универсальных админ-форм; backend RBAC и каталожная валидация остаются окончательной границей.

## Что нельзя объявлять завершённым без полевой проверки

- Авторизованные браузерные маршруты ADMIN/судьи/участника: 320, 390, 768, 1440, 1920 px, физическая клавиатура iPhone/Android, VoiceOver/TalkBack, задержки сети и повтор после ошибок.
- Реальные сохранения в Postgres и галереи RustFS, права командиров, импорт истории и профилей без владельца; не тестировать разрушительные операции на реальной базе.
- Сводка статического сканирования показывает потенциально неподписанные поля вне исправленных маршрутов. Их нужно подтверждать DOM/Accessibility tree: компонент `<label>` может быть на уровне вызывающего элемента, а не в той же функции. Без проверки не считать все предупреждения ошибками.
- Официальный командный зачёт требует согласованных правил очков; не считать отдельные личные места командными баллами.

**Критерий:** PR с полным CI → squash в `main` → одинаковый релизный SHA на Ubuntu frontend/API → read-only browser smoke. Это завершающий барьер данного изменения, **не** закрытие всего мастер-плана.
