# Web Push Implementation Plan

> **For agentic workers:** execute inline with test driven development. The owner already authorized autonomous implementation and waived further requirements questions.

**Goal:** opt-in browser push for registration opening, event reminders and administrator announcements.

**Architecture:** separate subscriptions and durable message/delivery queue; per-device consent and category preferences checked again before dispatch. A dedicated encrypted Web Push transport accepts only known browser push services and publicly routable DNS answers. Existing transactional email stays separate.

**Tech Stack:** NestJS, Prisma/PostgreSQL 18, web-push, React, service worker.

**Spec:** `docs/USD_MASTER_PLAN.md`, section 11.

## Global Constraints

- No provider sends, live migrations, production database changes or historical import.
- Additive migration `20261030061000_push_subscriptions` only. No committed VAPID secrets.
- iOS requires installed Home Screen PWA (16.4+) and a direct user gesture.
- ADMIN or custom `notifications` permission controls campaigns; all self service is scoped to authenticated user.

## Review Focus

- Endpoint forgery/private DNS: reject before storing and before connecting, pin the validated address.
- Account/resource isolation: cannot read/delete/take over another user's subscription.
- Consent withdrawal/preferences: queued work skips after opt out; no prompt before a click.
- Provider 410/404 and transient failure: expire subscriptions, bounded delayed retry, safe lease recovery.
- Notification click: same-origin allowlisted app paths only.
